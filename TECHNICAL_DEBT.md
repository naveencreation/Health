# Calorify — Technical Debt & Risk Register

Compiled 2026-11-05 from a read-only, module-by-module analysis of branch `cmd-v7`. **No code was changed.** Recommendations are suggestions only.

A second read-only validation pass on the same day did three things:
- re-checked the nine critical areas
- analysed the screens and docs the first pass had skipped
- added the entries marked *(2nd pass)*

The validation dossiers, the dependency and impact analysis, and the prioritized roadmap (tasks RM-00a to RM-39) are in [IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md).

**How to read this file**
- **Confirmed** means the defect follows from code that was read: a path and line are given.
- **✔** in the "Re-checked" column means the claim was re-read in the code during one of the two validation passes. Unmarked confirmed items rest on a single analysis read, usually by a delegated module analysis, and have not had that second read.
- **Potential** means a risk that needs a device, a Firebase console or a runtime check before it can be called a defect.
- Line numbers are approximate. They drift as code changes.

**Priority scale**
- **Critical:** silent loss of user data in normal use.
- **High:** wrong data written or shown, a privacy or security gap, a broken flow, or a blocked developer workflow.
- **Medium:** incorrect behaviour at the edges, performance, or maintainability that is likely to cause bugs.
- **Low:** hygiene.
